# Localisation

English (`en`), Sinhala (`si`), Tamil (`ta`). Both apps share one contract.

## Using it

```tsx
import { useT, useI18n } from "@lib/i18n";        // mobile
import { useT, useI18n } from "@/lib/i18n";       // web

const t = useT();
t("driver.home.greeting", { name })                // "Hi {{name}}!"
t("driver.trips.count", { count: n })              // picks ...count_one / ...count_other

const { locale, setLocale, formatDate, formatNumber, formatCurrency } = useI18n();
```

The context default is a working English translator, not a throw, so a component
renders correctly in a test or any tree that has not mounted the provider.

## Catalogues

`apps/mobile/locales/<locale>/` and `apps/kaduna-web/src/locales/<locale>/`, one flat file
per namespace, merged by `index.ts`. Keys are fully qualified in the file, so a key never
depends on which file it lives in.

Lookup falls back locale → English → **the key itself**. A missing translation shows as
`driver.home.greeting` on screen: obvious in QA, and never a blank button.

## Rules

- **Keys name meaning, not English words.** `emergency.whatsWrong.title`, never
  `emergency.whatsWrong.whatIsWrong` — rewording the English must not invalidate a translation.
- **Module-scope data holds keys, not calls.** Arrays and maps at module scope are evaluated
  once at import, so `t()` there would freeze the locale. Store `labelKey: "…"` in the data
  and call `t(item.labelKey)` at render.
- **Never concatenate translated fragments.** Word order differs in Sinhala and Tamil. Use
  `{{placeholders}}`.
- **Plurals are `_one` / `_other`.** All three languages have exactly two categories, so
  there is no ICU machinery here.
- **Enums stay enums.** `ServiceType`, statuses and route strings are never translated; only
  the label maps that render them are.

## Glossary — leave these in English

Brand and product names (`Kaduna.lk`), technical initialisms drivers already read in English
(`OBD`, `OBD-II`, `GPS`, `SMS`, `NIC`, `ABS`), the currency code `LKR`, vehicle makes and
models, plate numbers, garage and insurer names, and anything sourced from the database.

Database content is deliberately out of scope: garage names, part listings and insurance
company names are content, not chrome.

## Checking

```
node scripts/check-i18n.mjs            # keys used in code vs the catalogues
node scripts/check-i18n.mjs --strict   # also fails on gaps in si/ta and orphaned keys
```

## Known limits

- **No per-locale URLs on the web.** `output: "export"` rules out middleware, so the
  marketing landing page has no localised SEO. Restructuring under `src/app/[locale]/` with
  `generateStaticParams` is the upgrade path.
- **Server error text stays English.** ~32 sites render a raw `err.message` from dispatch.
  Mapping those to error codes is a separate change.
- **The questionnaire copy is duplicated** between mobile `app/(emergency)/` and web
  `src/lib/triageFlow.ts`. Keys are identical on both sides, so lifting it into `contracts/`
  is mechanical when someone wants to — it needs Metro `watchFolders`, which touches the
  release build, and was kept out of this change on purpose.
